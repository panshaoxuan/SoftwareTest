# 文件上传模块：需求—风险—用例矩阵

## 1. 文档目的

本矩阵用于建立文件上传模块的可追溯关系：

```text
业务需求（R） → 质量风险（RK） → 测试用例（TC）
```

它是后续自动化脚本、缺陷清单和测试报告的统一编号来源。测试执行时，缺陷应至少关联一个 `TC`，测试报告应按 `R` 和 `RK` 汇总覆盖情况。

## 2. 测试范围与基线

### 2.1 本次模块范围

- 普通文件上传：小于或等于 10 MB
- MD5 秒传与重复文件处理
- 大文件分片上传：大于 10 MB
- 分片断点续传、合并与清理
- 上传认证、参数校验和基本安全
- 上传结果在文件列表、MySQL、FastDFS、Redis 中的一致性

不将下载、分享和 AI 文件描述作为主流程；AI 描述仅作为上传成功后的非阻塞副作用观察项。

### 2.2 已知实现基线

| 项目 | 当前基线 |
|---|---|
| 普通上传阈值 | 前端代码为 `file.size > 10 MB` 才切换分片，因此恰好 10 MB 走普通上传 |
| 普通上传接口 | `POST /api/md5` → 未命中后 `POST /api/upload` |
| 分片接口 | `POST /api/chunk_init` → `POST /api/chunk_upload?md5=&index=` → `POST /api/chunk_merge` |
| 分片大小 | 10 MB |
| 认证 | token 与 user 一起参与接口校验 |
| 存储 | FastDFS 保存实体文件；MySQL 保存 `file_info`、`user_file_list` 等元数据；Redis 保存分片状态 |
| 前端反馈 | 上传进度、成功/失败提示、重复文件提示、上传后刷新列表 |

> “恰好 10 MB 是否走普通上传”是需要产品确认的边界规则；在确认前按当前代码作为测试基线，并将其列为风险。

## 3. 需求清单

| 需求ID | 需求描述 | 验收要点 | 优先级 |
|---|---|---|---|
| R-01 | 用户可上传普通小文件 | 合法登录用户上传 ≤10 MB 文件成功；响应成功；文件可在列表看到 | P0 |
| R-02 | 支持多种文件类型和文件名 | 文本、图片、PDF、压缩包及中文/空格/特殊字符文件名可处理，名称不被错误截断 | P1 |
| R-03 | 支持空文件及边界大小 | 0 字节、恰好 10 MB、略大于 10 MB 的行为明确且前后一致 | P1 |
| R-04 | 上传前进行 MD5 检测 | 客户端计算 MD5；先调用 `/api/md5`；MD5 未命中才发送文件实体 | P0 |
| R-05 | 支持秒传 | 已存在文件可复用实体文件；当前用户建立关联；不产生重复实体 | P0 |
| R-06 | 正确处理重复上传 | 同一用户重复上传相同文件得到明确结果，不重复插入用户文件记录 | P1 |
| R-07 | 支持大文件分片上传 | >10 MB 文件按 10 MB 分片，初始化、逐片上传、合并均成功 | P0 |
| R-08 | 支持断点续传 | 初始化返回已上传分片；客户端跳过已完成分片，仅补传缺失分片 | P0 |
| R-09 | 保证合并完整性 | 缺片不能合并；完整合并后文件内容、大小、MD5 正确 | P0 |
| R-10 | 支持失败重试和幂等处理 | 单片失败可重试；重复提交同一分片不会破坏最终文件 | P1 |
| R-11 | 上传接口需要身份认证 | 无 token、过期 token、用户不匹配请求被拒绝，不写入业务数据 | P0 |
| R-12 | 参数和文件名安全校验 | 非法 MD5、大小、分片索引、文件名和超限请求被拒绝或安全处理 | P0 |
| R-13 | 上传状态持久化一致 | 成功后 MySQL、FastDFS、文件列表状态一致；失败不产生错误关联 | P0 |
| R-14 | 分片临时状态可清理 | 合并完成或任务失效后 Redis 记录、临时分片文件和目录按规则清理 | P1 |
| R-15 | 前端提供可理解反馈 | 进度从开始到完成；成功、失败、重复、登录过期均有正确提示；不会重复触发上传 | P1 |
| R-16 | 上传性能满足基本可用性 | 小文件、大文件上传耗时和超时行为可观测；并发时服务不崩溃 | P1 |

## 4. 风险清单

| 风险ID | 风险描述 | 影响 | 可能性 | 风险等级 | 主要应对 |
|---|---|---|---|---|---|
| RK-01 | 普通/分片路由阈值判断错误 | 文件上传失败或走错流程 | 中 | 高 | 覆盖 10 MB 边界与路由断言 |
| RK-02 | MD5 计算错误或客户端与服务端不一致 | 错误秒传、文件损坏、重复存储 | 中 | 高 | 固定样本校验 MD5、上传后内容校验 |
| RK-03 | 秒传重复插入记录或实体文件 | 数据重复、列表异常、存储浪费 | 中 | 高 | 同用户/跨用户重复上传及 DB 断言 |
| RK-04 | multipart 字段顺序/字段名不兼容 | 普通上传全部失败 | 中 | 高 | 接口契约测试和真实请求抓包 |
| RK-05 | 分片缺失仍允许合并 | 生成损坏文件 | 中 | 严重 | 缺片合并负例、内容/MD5 校验 |
| RK-06 | 分片索引越界、重复或乱序处理错误 | 分片覆盖、合并错序或服务异常 | 中 | 高 | 索引边界、乱序、重复片测试 |
| RK-07 | 断点状态与临时文件不一致 | 无法续传或误判已完成 | 中 | 高 | Redis 有/无记录与文件缺失组合测试 |
| RK-08 | 合并中断后无法恢复或清理不完整 | 临时文件泄漏、重复合并、脏数据 | 中 | 高 | 中断注入、重试、清理断言 |
| RK-09 | token 校验缺失或 user 可伪造 | 越权上传、篡改他人分片 | 低~中 | 严重 | 未授权、过期、跨用户流程测试 |
| RK-10 | 文件名未安全处理 | 路径穿越、脚本注入、乱码或截断 | 低~中 | 严重 | 恶意/超长/Unicode 文件名测试 |
| RK-11 | 文件实体与数据库事务不一致 | 孤儿文件或无实体记录 | 中 | 高 | FastDFS/DB 故障注入与补偿检查 |
| RK-12 | 上传失败后前端状态未复位 | 页面持续 loading，无法再次上传 | 中 | 中 | UI 失败后重试测试 |
| RK-13 | 前端重复触发请求 | 重复文件、竞态和额外负载 | 中 | 中 | 快速连续选择/拖拽测试 |
| RK-14 | 超时、断网、并发导致服务不稳定 | 用户体验差或服务不可用 | 中 | 高 | 网络模拟、超时和并发基线 |
| RK-15 | Redis/临时目录未按规则过期清理 | 磁盘和缓存持续增长 | 中 | 中 | 合并后、过期后资源检查 |

## 6. 覆盖与执行规则

### 6.1 最小准入集

以下用例全部通过，才认为上传模块具备基本测试准入条件：

`TC-N-001`、`TC-N-002`、`TC-B-002`、`TC-B-003`、`TC-M-003`、`TC-M-004`、`TC-C-001`、`TC-C-006`、`TC-C-007`、`TC-S-001`、`TC-S-003`、`TC-D-001`、`TC-D-002`。

### 6.2 高风险优先级

优先自动化 `RK-02`、`RK-03`、`RK-05`、`RK-07`、`RK-09`、`RK-11`；这些风险一旦发生，可能造成文件损坏、数据丢失或越权。

### 6.3 需求变更处理

如果产品确认 10 MB 边界、空文件、重复文件或失败清理的规则与当前实现不同，应先更新本矩阵的 `R` 和验收要点，再修改测试预期，避免“测试通过但需求错误”。

## 7. 追踪统计模板

执行后在测试报告中填写：

| 指标 | 计算方式 |
|---|---|
| 需求覆盖率 | 至少有一个已执行用例的需求数 / 需求总数 |
| 高风险覆盖率 | 至少有一个已执行用例的高风险数 / 高风险总数 |
| 用例自动化率 | 已自动化用例数 / 用例总数 |
| 用例通过率 | 通过用例数 / 已执行用例数 |
| 数据一致性率 | 通过 `TC-D-*` 的任务数 / 执行任务总数 |
| 缺陷发现率 | 发现缺陷的用例数 / 已执行用例数 |
